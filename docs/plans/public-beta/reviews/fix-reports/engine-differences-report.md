# Engine differences review and gates

The earlier review missed two driver problems. Firefox 133 supports a non-unit pixel ratio, which Retest refused. That bounded defect is fixed. The native-table refusal is also too broad for the conformance team table: Firefox exposes the same seven rows as Chrome, but the driver refuses them before asking. That policy needs a broader table review, so it remains open with a reproduction. The later named-cell lookup really differs.

The expectation mechanism had four gaps. A conformance declaration could skip or leave a case absent, or use an arbitrary regex. A filtered shared-suite run could exit successfully with a declaration naming no case. A case could also catch a stale-declaration error and clear it; the suite now retains rejected checks and marks only successful comparisons checked. A declaration could also relabel an intentional Chrome refusal as an engine difference by adding literal text and a source anchor to its generic failed outcome. All four are fixed. Conformance declarations are limited to normally passing cases, so an already expected Chrome failure cannot be redeclared as a difference. Conformance declarations now require a failure or refusal, a source line and literal message text; A7's only variable is the failing event's recorded look count. A filtered suite still fails if a declared case never asserts. No declaration accepts Chrome's outcome alongside its own.

## Driver defects

1. **Firefox pixel ratio, fixed.** Raw `browsingContext.setViewport` with viewport 600 by 500 and `devicePixelRatio: 2.625` answered success and changed the page's ratio from 1 to 2.625 (`probe-before.log`). Retest previously refused the same request. `browser.ts` now permits a pixel ratio, and the shared actions suite checks width 600, height 500, ratio 2.625 and zero touch points. The phone refusal's exact message no longer names the ratio. Two direct regression expectations were updated in `tests/unit/firefox-browser.test.ts` and `tests/integration/firefox-refusals.test.ts`; these bounded companion changes are outside the lane's listed test files. No capture code was touched.
2. **Firefox native-table row refusal, open.** Reproduce under the lock with `.retest/scratch-engine-differences-review/probe.test.ts`: start Firefox 133.0.3 through Launch Services, open the original `/workflow/team` fixture, and call `browsingContext.locateNodes` with accessibility role `row`. It returns 7 rows; `cell` returns 24 and `columnheader` named Role returns 1. Chrome reads 7 rows. `page.execute({ kind: 'observe', locator: { by: 'role', role: 'row' } })` instead refuses `unsupported`, naming layout versus data tables. `accessible-names.ts` tests only whether any visible native table exists. The next named cell Grace Hopper is absent from Firefox's raw accessibility lookup, so removing all table/name protection would be wrong. No driver policy was narrowed from one agreeing fixture. The declaration continues to assert the exact current refusal, with this defect stated in its proof.
