# Fable review of Phase 1

3 October 2026. One review of the whole phase against the invariants in [release-0.1.0.md](../release-0.1.0.md), after each lane had been reviewed on its own. A first attempt died on the model's session limit while reading the diff and wrote nothing; this one ran at high effort and split the reading between five read-only reviewers, each with one question, while the reviewer kept the judgement, wrote the combined secrets test, reran the proofs and made every change below. Claims from the reviewers and from the orchestrator's separate claim-to-test maps were checked against the code before anything was changed. Nothing here loosens what a passing test means: where a pinned expectation was changed, the change is a decision named below.

## Findings fixed

Each with the file, a failure scenario, its severity, the change and the test that proves it.

1. **A proxy password reached the failure of a navigation that went through it.** `src/browser/browser.ts` handed the page the configured proxy server as given, and `navigationFailed` in `src/browser/navigation.ts` wrote it into the message and `details.proxy`. The config reader refuses a server with a user name, but a host that builds its config in memory, as Rehearsal does, is not refused. Scenario: `proxy: { server: 'http://ada:hunter2@127.0.0.1:8080' }` and a `goto` that fails through it: `hunter2` in `events.jsonl`, `result.json`, both reports, `inspect` and the answer the test process received. High. Fix: the page holds the address through `withoutCredentials`. Proof: `tests/integration/secrets-across-lanes.test.ts`, the test `opens nothing through a proxy that refuses the connection`, on real Chrome, which also records that Chrome answers `net::ERR_NO_SUPPORTED_PROXIES` to a proxy address with a user name in it.

2. **Every value of `RunOptions.testEnvironment` was written whole into the execution record and hashed into the configuration fingerprint.** `src/runner/fingerprint.ts` copied the host's environment into `settings.environment` and only replaced values the redactor knew. Scenario: a host passes `SERVICE_TOKEN` without declaring it a secret: the token in `test.started`, `result.json` and `inspect --json`, and inside `configuration.sha256`; and `PATH` or `TMPDIR` make the fingerprint differ per machine, which defeats the unchanged-configuration gate. High. Fix: the record and the fingerprint hold the variable names alone, sorted (`ExecutionSettings.environment: string[]` in `src/protocol/execution.ts`). Proof: `tests/unit/runner-fingerprint.test.ts` (`the environment is recorded by name alone...`, and the changed-value case in `changes with a budget...`), `tests/unit/runner-replay-run.test.ts`, the protocol samples.

3. **`retest list` gave the collection process the config's secret variables.** `collectFiles` in `src/runner/run.ts` hid only the judges' variables, while a run hides both. Scenario: `secrets: { password: env('TASK_PASSWORD') }` and a test file whose top level reads `process.env.TASK_PASSWORD`: the value in a process that runs project code. Medium. Fix: `collectFiles` hides `secretVariables(config.secrets)` too. Proof: `tests/unit/evaluation-commands.test.ts` (`list, with a secret whose value is read from the environment`, with the control that sees it without the secret).

4. **A failure the parent saw for itself was dropped when no AI check had failed and the process claimed a pass.** `withEvaluationFailures` in `src/evaluation/run-evaluations.ts` returned the process's report whenever `recorded` was empty, and `#verdict` in `src/runner/running-test.ts` accepted `status: 'passed'` without reading `#observed`. Scenario (the lane's own technique): a test process looks at a missing element, reports the failed assertion the parent accepts on that look, then ends its test `passed`: status `passed`, exit 0. High. Fix: what the parent saw (a page command's failed answer, a check that failed on a served look, a refusal it gave, its own stop) is a candidate to lead whether or not an AI check failed; a command answered after the parent's own stop is not a second failure. Proof: `tests/support/files/forged-pass.retest.ts` run by `tests/unit/runner-observations.test.ts` (`a real test process that claims a pass after the parent failed its assertion...`, status `failed`, `check_failed`, ending `assertion_failed`, exit 1) and the pure cases in `tests/unit/evaluation-contract.test.ts`.

5. **The process could set the status `inconclusive` by naming an AI check class the parent never recorded.** Same function: an `evaluation_inconclusive` reported with no parent record led, and `testStatus` made the test `inconclusive`, exit 2, while `attemptEnding` said `test_error`; the evaluation record claimed such claims were dropped. Medium. Fix: an AI check class the parent neither recorded nor refused is an error of the test, with the process's words kept; a refusal the parent gives because the run has no judges is now one of its observations, so the honest `evaluation_error` stands. Proof: `tests/unit/evaluation-contract.test.ts` (`an AI check outcome the process reports that the parent neither recorded nor refused is an error of the test...`, and the retitled `disowns a check failure...`).

6. **A failed required page check became `error` when a later check lost the page.** `runHostChecks` in `src/runner/run-host-checks.ts` chose one of ours over an application failure, the opposite of the rank the lanes settled. Scenario: check 1 fails on the app, the browser dies before check 2: `session_lost`, status `error`, exit 2, ending `crashed`, the required failure only in `details.also`; in Rehearsal, "ours" and restarted, so the customer never sees the failed check. Medium. Fix: the first check that failed on the app leads, ours only when none did. This reverses a rule pinned before this phase (`tests/unit/runner-host-checks.test.ts`, `a failure on our side after a failed check`), whose expectation now reads `failed`, `host_check_failed`, ending `required_check_failed`, exit 1, with the loss in `also`; the orchestrator should confirm the reversal.

7. **A host AI check that never ran had no event, so a result rebuilt from the events listed fewer checks than `result.json`.** `#recordNotRun` in `src/evaluation/attempt.ts`. Medium. Fix: it writes `evaluation.finished` with verdict `not_run`, the parent's. Proof: `tests/unit/evaluation-runs.test.ts` (`are listed as not run when the body failed...`, the rebuilt result equal to `result.json`). Page host checks that never ran still have no event; see open items.

8. **Tests that could not fail, or asserted less than their title.** Each tightened: `tests/unit/evaluation-contract.test.ts` (a required fail must be a failure before its message is read), `tests/unit/runner-preparation.test.ts` (the cut reasons must exist and be long), `tests/unit/diagnostics-run.test.ts` (status asserted), `tests/unit/diagnostics-policy.test.ts` (the partial-capture failure's class), `tests/integration/test-controls.test.ts` (a duration must exist), `tests/integration/participants-four-sessions.test.ts` and `participants-accounts.test.ts` (the deliberate failure is the intended `check_failed` at its intended check). Medium.

9. **No one test carried every credential at once.** New: `tests/integration/secrets-across-lanes.test.ts`, a host program on real Chrome with a proxy password in a config built without validation, two fake judges keyed from `RETEST_EVALUATION_ANTHROPIC_KEY` and `RETEST_EVALUATION_OPENAI_KEY` with made-up values that each echo its key back, a host AI check, two host secrets the page sends into messages, errors, queries, paths, headers, cookies, a stack and a preview Chrome cuts, diagnostics capturing all of it, and the failed proxy navigation of finding 1. It then reads every file of the run folder for each value whole, JSON-escaped and in every ten-character part, the host's output, `inspect`, `inspect --test` and `inspect --json`, the test file's process (all four variables absent) and the app server Retest started (the judge's variable printed empty, so withheld, not redacted). It checks the placeholders are present, so what it proves is redaction, not absence. Passes: `/tmp/retest-fable-secrets-lanes.log`.

10. **The guide said a reader built before this phase would cope.** It did not say the opposite, which is the fact: every object refuses unknown keys, and every attempt now writes `execution` and `ending`, so a reader built before this phase refuses every new folder. Added to the run-folder section of `docs/guide.md`, with the RegExp locator widening. Low.

11. **Documentation that claimed more than its tests show.** Thirty-odd sentences in `docs/guide.md` and the records `proofs/loader.md`, `proofs/evaluation.md` and `proofs/diagnostics.md` were narrowed to what a named test or proof shows, each checked against the code first: tsc refusals never run, "every other warning prints" untested, which `paths` shapes Retest checks, the three hooks the child registers, the hook stepping aside under `--experimental-transform-types`, measurements by hand with no log, the Playwright resolve order, the decorator hint's source, the doctor probe, row names and `deltaY` and downloads not checked, the title cut and the look floor as the code has them, fake-only coverage listed as such, the secret fill leaving on focus not mid-typing, the `EvaluatorFactory` example made self-contained, the strict policy's exit when a match was also found, the four-times pre-cut before the redactor, cut fields with no length, slug redaction at 16 characters, `inspect`'s 50 and 100 caps, and the records' "every claim exercised" wording. One test title corrected (`tests/unit/evaluation-runs.test.ts`: a judge that never answers). The untested paths each map named are listed in each record's "what remains" section. Low to medium.

12. **A test file's process that left a process of its own behind hung the run.** `TestFileProcess.kill()` and `close()` in `src/runner/test-file-process.ts` waited for the child's `close` event, which comes only once every holder of its output pipes has gone; a test that starts a server with `stdio: 'inherit'` and passes left the run waiting forever after the child had exited, and `retest list` the same through `collectFile`. High. Fix: once the process has exited, its output is read for one more second, then its pipes are let go and `closed` settles; `close(graceMs)` kills only a process still alive, so `forced` means a kill. Proof: `tests/support/files/grandchild.retest.ts` run by `tests/unit/runner-process.test.ts` (`closes a bounded time after it exits, though a process it started still holds its output pipes`).

13. **A browser could launch after the pool had closed.** `BrowserPool.close()` in `src/runner/browser-pool.ts` closed the browsers already launched; a setup queued behind one in flight still ran `#first`, launched, announced `browser.started` after `store.close()` and stayed connected. Medium. Fix: a setup that starts once the pool is closing is refused with the run's interruption, a launch that finishes while it closes is closed with the rest and never handed out, and the close waits for the setups in flight. Proof: `tests/unit/runner-browser-pool.test.ts` (`a setup queued or in flight when the pool closes launches nothing the close leaves behind`).

14. **Guide sentences that contradicted the code**, each checked and corrected in `docs/guide.md`: the config keys table lacked `evaluation` and `diagnostics`; "only the first problem is named" (every problem is, except an unreadable target); Firefox and WebKit targets also take `viewport`; "2 wins over 1" (a failed test exits 1 before errors, not-run and undecided tests, `src/runner/outcome.ts`); the example's "16 test runs" (15 tests and the setup); page looks take observation ids and write no event, so ids can skip; `judgedBy: 'parent'` covers `toHaveURL` and `toHaveTitle`; a cleanup-only declaration after a failed preparation is left alone (`src/runner/preparation.ts`); which preparation strings are refused at 500 characters and which cut; sessions release after the host cleanups too; `browserStorage` is `saved`, not "restored". Low.

## Decisions recorded, no change

- **A command stopped after its input was written keeps the stop's class** (`interrupted` or `timeout`) with `details.inputSent: true`, rather than `outcome_unknown` (`src/browser/page.ts` with `src/runner/command-failures.ts`; pinned by `tests/integration/session-contract.test.ts` and `tests/unit/browser-input-dispatch.test.ts`). `outcome_unknown` is kept for a browser lost after dispatch, where nothing will ever answer; a stop names why the command ended and `inputSent` whether input went, and the plan's invariant, that cancellation cannot undo sent input, is what `inputSent` records. The three-way dispatch state still reaches no event, as the inventory says.

## Findings left, with the reason

- **A test file's process blocked in a loop outlives a parent killed with SIGKILL** (`src/runner/child-program.ts` exits only through its `disconnect` handler, which a blocked event loop never runs; reproduced by the cancellation reviewer with `tests/support/files/endless-loop.retest.ts`: the child at PPID 1 and full CPU). A parent that exits any other way kills it through the exit hook. macOS has no kill-on-parent-death; a watchdog thread in the child or a wrapper process would be new machinery. Open; the comment in `tests/integration/matrix-reporting.test.ts` that says the process ends on its own is true of every exit but SIGKILL.
- **A chord, click or tap stopped partway leaves keys or the button held** (`src/browser/input.ts`); a later action in the same test runs with the modifier down, and no test stops between the keys of a chord. Open.
- **`signalGroup` in `src/runner/app-server.ts` rethrows EPERM** where `chromium-process.ts` reads it as "still there", so a group with only unreaped or other-user processes can make `runFiles` throw with no `result.json`; and a group still there after SIGKILL records no `cleanup_failed`. Open, low.
- **A `goto`, `reload` or history move whose navigation request was written but timed out** answers `timeout` with no `inputSent` (`src/browser/navigation.ts`). Open, low.
- **The parent has no `uncaughtException` or `unhandledRejection` handler** (`src/cli/program.ts`), so a crash exits 1, the code of a failed test. Open, low.
- **No test sends SIGINT to the whole process group as Ctrl+C does**; the interrupt tests signal Retest's process. Open.

- **Page host checks that never ran have no event**, so a rebuilt result lists `hostChecks` without them; this predates the phase (HEAD wrote them into `result.json` the same way) and needs a new event type or a rebuild rule that repeats the writer's conditions. Recorded, not changed.
- **A RegExp the test process sends runs in the parent, synchronously** (`patternMatches` in `src/protocol/locator.ts`, through `src/runner/observations.ts`): a catastrophic pattern from a test file blocks the parent and every worker; Node has no bounded regex execution. The pattern is the test author's own, so it is a self-inflicted hang, but it hangs the run rather than the file. Open.
- **Function-sourced credentials and secrets are learned when first read**, and `run.started` is written before that, so a function credential's value that appears in a host check's context or criteria reaches `events.jsonl` line 0; `result.json` is rebuilt late and clean. The replay record says this for check content. Open, needs a decision on reading function sources before `run.started`.
- **App servers and Chrome receive the config's secret variables**; only the test file's process is denied them. By design (an app may need them), the server log is redacted and the run's Chrome log is re-read at the end, but `doctor`'s browser log under `.retest/doctor/` is never redacted. Open.
- **`MediaProcess.start` spawns with the whole environment** and has no `hiddenVariables`; not on a runner path until the media pipeline is wired in. See the media section.
- **`Observation` gained required `checked` and `enabled`** (`src/protocol/commands.ts`): the driver contract a host's own launcher implements, not `events.jsonl`; an older driver fails typecheck, and would fail every `toBeChecked` at run time. Additive for folders, breaking for drivers; the records do not name it.
- **The parent's stop reason is lost from `ending` when the process had an earlier failure of its own** (`src/runner/running-test.ts` with `attemptEnding`): a soft failure then a lost browser ends `assertion_failed` with `outcome_unknown` only in `also`. Not a forged pass; `Ending` has one slot.
- **A judge's answer carries no request id**; the parent binds answer to request through the adapter's promise. Attempt fencing across restarts is Phase 5 work; noted so the contract gets a slot then.
- **`Ending.notRun` means two things**: the checks a skipped test never ran (absent) and the checks a not-run test never ran (listed). Event and result agree; wording only.
- **A strict `transportFailures` rule with `httpErrors` off counts neither record of an error answer with no body**; by the lane's rule that answer is one HTTP error, so this is the rule, not a defect.
- **The fake evaluator defaults an unknown criterion id to `pass`**, so a mistyped fixture passes; a fixture concern.
- **`tests/unit/protocol.test.ts` still accepts `input: 'script'`** on events though nothing emits it; schema width kept for old folders.
- **The 500 ms back-forward-cache allowance in `goBack` and `goForward`** has no unit test; the path runs on real Chrome in `tests/integration/lookup.test.ts` and `browser-navigation.test.ts`, where the restore arrives. Still a timing guess; a fake-session unit test would need the watcher driven through `Page.frameStoppedLoading` then a `BackForwardCacheRestore`.

## Media cancellation findings

Ten claims from a read-only trace of the media lane's cancellation paths were handed to a builder working only inside `media/`, `src/media/`, `proofs/media/` and the media record; the reviewer read its diff after. All ten were confirmed against the code; nine were fixed, each with a test that failed before the fix (`/tmp/retest-fable-media-client-before.log`: 18 pass and 7 fail against the original client), one is recorded. The record's table "Review findings and what changed" in [proofs/media.md](../proofs/media.md) names each.

1. A forgotten `close()` kept Node alive forever: the child and its pipes are referenced only while a recording runs or a start is unanswered, with no exit hook, since the media process already shuts down on the end of its input and a kill would orphan encoders (`src/media/client.ts`, `#attend`). Tests: a forgotten close, and SIGTERM to a child Node mid-recording leaving no process or file.
2. A forced `close()` returned before the lost recordings' encoders were stopped: `#close` now awaits every reclaim. Test: SIGSTOP on the media process, then `close(300)`.
3. An encoder wrapper whose leader exited while a forked child lingered was reported "exited on its own": after the grace the group is killed whenever anything is left in it, and waited for. Test: a `sleep 30 & exec ffmpeg` wrapper.
4. `kill(-pgid)` after the group was known empty: the two pointless kills are gone, and `mark_done()` in `media/src/recording.rs` moved before the stderr join so the watchdog and `Shared::stop` no longer signal in that window; the windows that remain need pidfd and are listed under "Not shown".
5. Ids over 200 characters and frames over 64 MiB are refused by the client before they are sent (`MAX_ID_CHARACTERS`, `MAX_FRAME_BYTES` exported from `src/media/protocol.ts`), with a 201-character unit case in `media/src/server.rs`.
6. A `started` after the client's timeout is kept as a recording the client finishes at once and reclaims if the process then dies. Test through a `late-start` stand-in mode.
7. The first stdin error is kept and named, and `#unavailable` reads `destroyed` too, so a frame after the pipe broke is `not_sent`. Test through a `close-input` mode.
8. `#errors` capped at the newest 64; the record's bounds list now names the queues, the read-ahead, the decode buffers and their sum.
9. The first start joins the ffmpeg probe on the loop, so a hung ffmpeg holds the process's input for up to about 28 s: recorded under "Not shown", not changed.
10. Record lines beyond their tests corrected: a test with a start and a finish pending when the process dies; the ended-or-closing test now asserts `stopped`, an empty encoder group and no `.partial`; the sleeps in the dies tests and in proof step 9 replaced by waits on the file; the one-second grace dependence stays and is recorded.

Not verified by the builder: pgid reuse in the remaining windows, the 28 s stall itself, Linux. It reported one slip: a `pkill -f "sleep 30"` broader than its own processes, with nothing else matching at the time. Its gates: `cargo test` 39 and 25, clippy and `cargo fmt --check` clean, release rebuilt, 25 of 25 client tests, the proof with nothing left, both compilers clean on the proof (`/tmp/retest-fable-media-*.log`).
