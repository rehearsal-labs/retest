Brief: [codex/phase-4/html-report.md](../codex/phase-4/html-report.md), bound by [codex/phase-4/common.md](../codex/phase-4/common.md). Written 5 October 2026 on the tree with Phase 3 and the review fixes uncommitted on top of `b59eed5`, while seven other lanes edited it.

## What was built

A static report of one run, written as `report.html` into the run folder, made from `events.jsonl` and `result.json` alone, the folder's files read through the store's safe read.

- `retest run --reporter html` prints the human report and, once the run ends, writes the file and prints `Report  <folder>/report.html`.
- `retest report <run-folder>` builds it from a folder that already exists, finished or not, replacing an earlier one. A folder without `result.json` is rebuilt from its events, warned about on stderr, and the report says the run did not finish.

## Decisions

- **One reading of the outcome.** The failure part of the page is built from the terminal's own `FailureCard`; the summary rows use the same counting functions as the terminal summary; the evidence and every test status come from the result. The `--reporter html` file and `retest report` share one builder.
- **The run's report reads the result the run hands its reporters.** The runner writes `result.json` after its reporters end, so the file `--reporter html` writes can be overtaken by a later reporter failure or a `result.json` that could not be written; `retest report` on the folder gives the final state. Said in the guide.
- **A report that cannot be written fails the reporter**, which the runner records as `reporting_failed`, as for any reporter.
- **Page addresses are text, never links.** `pageHref` is not used: nothing in the report points off the run folder.
- **The policy:** `default-src 'none'; img-src 'self' file:; media-src 'self' file:; style-src 'sha256-…'; script-src 'none'; base-uri 'none'; form-action 'none'`. Shown by a probe on Chrome 154.0.8037.93 headless, run by this lane's first worker and not repeated: on a `file://` page `img-src 'self'` loads an image beside the page and also one in the folder above it; `'none'` blocks it; a hashed `style-src` applies. So on a file address the policy does not keep loads inside the folder; the report does, by linking only to portable references. `file:` is there for browsers that read `'self'` more narrowly on file addresses (not tried).
- **Evidence state is derived from today's records** until the recording-runner lane's evidence-status events land; then those events are read first and this derivation stays for older folders.
- **Recordings, built on the recording-runner lane's shapes as they stood when that lane stopped** (`src/protocol/recording.ts`, `recording.started`, `recording.finished`, `capture.*`, `artifact.removed`, `TestResult.recordings`, `evidenceStatus`): the report names each recording, shows its video and its gaps, and never calls a test's evidence complete while its result names a gap. The timeline names recording and pixel-policy events in words. The store's `eventArtifactReferences` does not know recordings yet, so the report's own folder listing names recording files from the result. The seek from a step to the video's time is not built: it needs a script, its hash in the policy and the clock mapping in a data block, and that lane's shapes were not yet announced as settled.
- **Thumbnails** are the screenshots scaled by the style sheet, linked to the full file. The media lane's thumbnail files are not yet named by any record.
- **One data block, never run.** The outcome travels in the file as JSON too (`<script type="application/json" id="retest-outcome">`), for CI that keeps only the report and for agents. The policy keeps `script-src 'none'`; a JSON data block is not a script the browser runs. Its text goes through `scriptJson`, so a test title holding `</script>` is written `\u003c/script\u003e` and reads back whole (`reporters-html-safety.test.ts`). The agreement test checks the block against the result, the page's marks and the terminal in all eighteen folders.
- **Opening the report through Retest's driver.** Retest's `goto` opens only http and https addresses (`src/browser/navigation.ts`, `resolveTarget`, in place since the first runner commit), so the integration test cannot give it a `file://` address. It serves the run folder over loopback instead, each request read as a portable reference through `readArtifactFile`, so the browser is given only what the safe read accepts from the folder, and every path asked for is kept and checked. Over http, `'self'` in the policy is the server's origin, which is narrower than Chrome's reading of `'self'` on a file address. Opening from the `file://` address itself was shown with Chrome's own headless screenshot (below), outside Retest's driver.
