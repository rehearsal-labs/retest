## Design decisions, with reasons

1. **Recording off changes nothing.** Without a `recording` block (or with `record: false`) and without `pixels`, the run makes no `RunMedia`, no `PixelCapturePolicy`, no recorder, writes no new event or field, and the failure screenshot path is untouched. Reason: the brief's "recording off is the default cost"; proved by unit test (below).
2. **Absence of `evidenceStatus` means not requested.** It is written on every `test.finished`, test result, `run.finished` and `result.json` only in a run that records some app. A recording run writes `not_requested` for an attempt with no recorded session (skipped, never opened pages, app not recorded).
3. **One media process per run, lazily.** `RunMedia.acquire()` starts it at the first recording, waits for `ready()`; an encoder that is not `ready` emits `media.failed` (`encoder_unavailable`), closes it and refuses every later recording. A crash emits `media.lost` (recordings counted, `restart`), the next `acquire` starts one more; after the second loss nothing more starts. `close()` closes every process the run started, the lost ones too, bounded by cleanup + 5 s, and returns a `cleanup_failed` run failure when the ownership layer cannot confirm one gone.
4. **Shutdown order.** In each attempt, recordings finish after diagnostics end and before the failure screenshot and before pages close (every exit path of `#runPrepared` goes through a `finally` that awaits `recorder.finish()`). At run end `#releaseMedia()` runs first in `#release()`: finish any recorder, close the media process (confirmed gone), apply `run_finished` retention, then native/browser close. So no change to the browser drivers' fast close was needed: frames are already in the media process before any browser is asked to close. The brief's optional anchored edits to src/browser/*, firefox, webkit and native session close were therefore not made.
5. **Media binary location.** `RunOptions.media` (`{ executable, ffmpeg? }`), else `RETEST_MEDIA_BINARY` / `RETEST_FFMPEG`; never a build folder. A missing binary is a `media_unavailable` evidence gap, never a test failure. The media-install lane's `src/media/locate.ts` (not on disk yet) should replace `mediaLocation` in src/runner/run-media.ts.
6. **Required evidence.** New failure class `evidence_incomplete` (ours, so `error`). `runOutcome` takes `evidenceFailure`: exit 2 and `complete: false` when every test passed; a failed test still gives exit 1 (the run failure is listed after others). Tests keep their observed outcome.
7. **Pixel policy wiring.** Active when the run records or an app states `pixels`. A secret fill calls `beginSecretEntry` just before `page.execute` and `endSecretEntry` after (input `sent` / `not_sent` from `details.inputSent === false` / `unknown`). The driver reports no field fact yet, so the fact is `{ kind: 'unread' }`, which the policy treats as showing text: the session is withheld from the first key until the page opens a new document (`navigation` with `document: 'new'`, fed to `pageLeft`) or the session ends. Failure screenshots ask `decide` before and after the capture (span from the request); a withheld one is `evidence.failed` with `withheld`.
8. **Frames during a stretch.** `PolicedSource` (src/runner/policed-source.ts) wraps the page's `frameSource`: each frame goes through `decide({ use: 'recording', span: { earliestUs: screencast start, arrivedUs } })`; a stretch suspends the recording's `CaptureSuspension`; when the stretch ends it stops the old screencast, resumes the suspension, then starts a new screencast from `page.frameSource(identity)` (a Chromium source captures once), so no frame painted during the stretch is kept and the first new frame is. Frames the policy withheld before hand-over are counted into `frames.withheld`.
9. **Records.** `recording.started` (identity, recording number, source, mode, path reference, size, fps, codec, container, route, keepFrames, `startedUs`) and `recording.finished` (`recording: RecordingRecord`) before `test.finished`. `RecordingRecord` carries status `complete | partial | unavailable`, named `gaps` (codes in `evidenceGapCodes`, src/protocol/recording.ts), path, partialPath, video facts, runner frame tally, media counts, withheld stretches, and `clock` (`videoZeroUs`, `durationUs`, shortened pauses): an event at `elapsedMs` is at video time `elapsedMs*1000 - videoZeroUs`, since frames are stamped with `microsecondsSince(runStart)` on the same monotonic clock as `elapsedMs`. A lost recording with a `.partial` left is `unavailable` with `partialPath` named and the words "whether it plays was not checked".
10. **Retention.** `keep: 'failures'` applies `planRetention`/`applyRetention` at `attempt_finished` for a passed attempt, with references the run built itself (`eventArtifactReferences` in artifacts.ts does not know recording events yet), emits `artifact.removed` first, and marks the record `removed: 'passed_attempt_recording'`; the rebuild applies the same from `artifact.removed`. `run_finished` retention removes unnamed `.partial` files; named partials are kept.
11. **Leftovers of killed runs.** `media.started` records the owner (this process's pid and `ps` start time). The first media start sweeps up to 16 sibling run folders of the run folder: those with no `result.json`, a `media.started` whose owner is gone (pid absent, or present with another start time) and `recording.started` events; each output goes to `media.leftovers(output, { remove: true })`, and `media.leftovers` events name what was removed. A run whose owner may still run, or whose host reading failed, is left alone.
12. **AI checks of frames.** `AttemptRecorder` implements the frames-evaluation lane's `AttemptRecordings` (`recording(app)`, `step(name)` from step events on the run clock) and is passed to `evaluations.attempt({ recordings })`. `keepFrames` is on only when the config declares judges; kept frames are released after the attempt.
13. **Event-field trap found:** an event body field named `sequence` overwrites the envelope's `sequence` (EventLog spreads the body after the stamp). The recording number is therefore `number` on `recording.started`.
