**Connections built**

`src/runner/native-pool.ts` owns startup, a runtime holder per desktop or device/runtime, session preparation and shutdown. It verifies the attempt, holder and native resource before startup; the runner passes the lease only after acquiring every part. Hidden credential variables are passed to native tool filtering, and explicit app environment overrides of those names are refused. `HeldApp.whenFree` waits for the native session and runtime to end. A failed or uncertain start retains its resource unless it explicitly proves that nothing launched. A failed shutdown keeps the lease held. The pool emits the ended record after successful cleanup even when the normal test-page cleanup was interrupted.

The native runtime opens the lifecycle session. The wrapper attaches the interaction client to its active session using the exact status route, without opening a replacement executor session. Native commands go to `NativeInteractionSession`, preserving its locator rules, one-match actions, actionability, serial lane, stale-reference checks and input ledger. The wrapper refuses changed launch settings instead of ignoring them and adds the lifecycle session's unexpected-end flag to state readings.

`src/runner/run-session.ts` starts native runtimes after the lease, opens one interaction session per native app, records each reset boundary and closes it before release. Simulator boundaries create a fresh device and delete it on close. macOS retains app data and keychain; a supplied `-reset` is an app request, not OS isolation. Browser prewarming was removed. Web browser and server setup still run concurrently, inside the acquired lease. The paired real run records its lease before either browser or native startup.

`src/runner/running-test.ts` routes native commands to the native layer and refuses forged web capabilities. The parent serves the scoped tree, records native generation and selected metadata, checks references and judges each submitted locator assertion itself. A forged passing verdict cannot replace the parent's failure. Tests verify selected state, stale launches, revocation after dispatched input and forged concurrent actions or looks. Unknown input is retained and not sent again.

Native configuration adds optional arguments and environment. Owned debugging/data switches and executor environment names are refused by name; malformed values are not quoted. **Native secrets through the runner**

The parent now types a `secret()` into a native app the way it types one into a web page, with the app's bundle id as the destination. `RunningTest` gives the resolver the bundle id the installed app's Info.plist names (`NativePageAdapter.bundleId`, from the session's execution identity) in place of a page address. `SecretFiller.resolve` then reads the secret only when `secretOrigins` names that exact id; base URLs play no part. Otherwise it refuses `not_actionable`, naming the app's id and the ids the secret may go to, and reads nothing: a function source is not called. The resolved fill carries the one id it was checked against. `NativePageAdapter.execute` refuses, `unsupported`, any secret fill that does not name its own app's id, so a fill resolved for another app reaches no executor route. Values are taught to the run's redactor before dispatch, as on the web.

The native pool now drives the executor client and session the runtime's `openSession` hands over. It no longer asks `GET /status` which session is active, and a runtime that hands none over gets no interaction session (`setup_failed`, the session it opened disposed). The pool also passes the run's redactor into its native tools, so the executor build log is redacted as the runtime logs are.
