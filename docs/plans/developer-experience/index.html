Design plan, 30 September 2026. Nothing here runs yet.

One test runner for web, phone and desktop apps, and for AI answers.

This page shows what using Retest would look like, from install to an eval run. Every command and output is what we plan to build. Timings, versions and prices in the samples are made up.

Chips mark when each part arrives. M1 is the first milestone in the brief. M2 comes next.

2

The config

M2

One map of apps. An app with one target can be written as that target. The last block lets every test file see your app names, secrets, test ids and tags, so the type check catches typos in them.

retest.config.tswritten by init
import { defineConfig, chromium, env } from '@rehearsal-labs/retest'
import { testIds } from './src/test-ids.ts'

const config = defineConfig({
  apps: {
    web: chromium({
      baseUrl: 'http://localhost:3000',
      start: { command: 'npm run dev', ready: 'http://localhost:3000' },
    }),
  },
  secrets: { password: env('TEST_PASSWORD') },
  testIds,                  // optional: your app's own list of test ids
  tags: ['smoke', 'slow'],
})

export default config

// Lets every test file see your app names, secrets, test ids and tags.
declare module '@rehearsal-labs/retest' {
  interface Register { config: typeof config }
}

If something already answers at ready, Retest uses it and leaves it running.

3

A regular test

M1M2

The same shape as Playwright and Vitest, so people and coding agents already know it. The first test uses only test ids and works in M1. The second uses roles, labels and a step, which come in M2.

tests/tasks.retest.tsyou write
import { test, expect } from '@rehearsal-labs/retest'

test('saves a task', async ({ page }) => {
  await page.goto('/')
  await page.getByTestId('task-title').fill('Release checklist')
  await page.getByTestId('save-task').click()
  await expect(page.getByTestId('saved-task')).toHaveText('Release checklist')
})

test('shows the count', { tags: ['smoke'] }, async ({ page }) => {
  await page.goto('/')
  const added = await test.step('Add two tasks', async () => {
    for (const title of ['One', 'Two']) {
      await page.getByLabel('Title').fill(title)
      await page.getByRole('button', { name: 'Save' }).click()
    }
    return 2
  })
  await expect(page.getByRole('listitem')).toHaveCount(added)
})

4

Hooks, data and signing in once

M2

A setup test signs in once for each target in a run. Tests that ask for its state start from a copy of it. Every other test starts signed out.

tests/sign-in.retest.tsa setup test, runs once per target
test.setup('signed-in', async ({ page }) => {
  await page.goto('/login')
  await page.getByLabel('Email').fill('qa@tasks.example')
  await page.getByLabel('Password').fill(secret('password'))
  await page.getByRole('button', { name: 'Sign in' }).click()
  await expect(page.getByRole('heading', { name: 'Tasks' })).toBeVisible()
})
tests/archive.retest.tsyou write
test.describe('archive', () => {
  test.beforeEach(async ({ page }) => {
    await page.goto('/tasks')
  })

  test('archives a task', { state: 'signed-in' }, async ({ page }) => {
    await page.getByRole('button', { name: 'Archive Release checklist' }).click()
    await expect(page.getByRole('status')).toHaveText('Archived')
  })

  test.for([
    { title: 'Release checklist' },
    { title: 'Ünïcode and emoji ✓' },
  ])('archives "$title"', { state: 'signed-in' }, async ({ page }, { title }) => {
    await page.getByRole('button', { name: `Archive ${title}` }).click()
    await expect(page.getByRole('status')).toHaveText('Archived')
  })
})

The saved state holds cookies, so it stays in the run folder and never goes into a report. Custom fixtures come later, in the same builder shape as Vitest's test.extend.

6

Every browser and engine

later

Give an app named targets, and every test that uses it runs once on each. Each target says what it really is: WebKit is the engine, and only safari() is Safari.

retest.config.tsnamed targets
import { defineConfig, app, chromium, chrome, edge, firefox, webkit, safari } from '@rehearsal-labs/retest'

export default defineConfig({
  apps: {
    web: app({
      baseUrl: 'http://localhost:3000',
      targets: {
        chromium: chromium(),              // open-source Chromium, or Chrome for Testing
        beta: chrome({ channel: 'beta' }), // branded Chrome: stable, beta, dev, canary
        edge: edge(),
        firefox: firefox(),                // stock Firefox over WebDriver BiDi
        webkit: webkit(),                  // the WebKit engine on Linux, not Safari
        safari: safari(),                  // real Safari: macOS only, one session per Mac
      },
    }),
  },
})

A test names the apps it needs. The runner takes all of them before it starts, or waits. The report reads as one timeline, whichever device each step ran on.

AI checks in a test

later

toMeet judges one answer against plain criteria. It waits for the answer to finish, captures it once, and asks the judge once. A verdict has to quote the answer word for word. When the judge can't give a checkable verdict, the result is inconclusive, never a pass.

tests/support.retest.tsyou write
test('support bot explains the return window', async ({ page }) => {
  await page.goto('/support')
  await page.getByLabel('Message').fill('Can I return shoes after 40 days?')
  await page.getByRole('button', { name: 'Send' }).click()
  await expect(page.getByRole('button', { name: 'Stop generating' })).toBeHidden()

  await expect(page.getByTestId('latest-answer')).toMeet([
    'Says returns are accepted for 30 days',
    { absent: 'A promise of an exception' },
  ])
})

11

Evals

later

One correct label proves little. An eval runs a feature over a dataset, scores each answer, and checks the rate against a gate. Plain code scores what code can check. The judge only scores meaning.

evals/labeler.retest.tsyou write
import { test, dataset } from '@rehearsal-labs/retest'
import { meets } from '@rehearsal-labs/retest/scorers'
import { z } from 'zod'

const Ticket = z.object({
  id: z.string(),
  input: z.string(),
  expected: z.enum(['billing', 'bug', 'feature', 'spam']),
  metadata: z.object({ critical: z.boolean().default(false) }).default({}),
})

const Labeled = z.object({ label: z.string(), reason: z.string() })

test.eval('ticket labeler', {
  apps: ['api'],
  cases: dataset('./evals/tickets.jsonl', Ticket),
  trials: 3,
  concurrency: 8,

  // run sees the input and metadata, never the expected answer
  async run({ api }, { input }) {
    const response = await api.post('/labels', { json: { text: input } })
    return Labeled.parse(await response.json())
  },

  scores: {
    label: ({ output, expected }) => output.label === expected,
    reason: meets({
      answer: ({ output }) => output.reason,
      criteria: ['Explains the label using facts from the ticket'],
    }),
  },

  gates: { label: 0.9, reason: 0.8 },
  critical: ({ metadata }) => metadata.critical,
  baseline: 'main',
  budget: { usd: 10 },
})
evals/tickets.jsonlthe same fields as Braintrust, LangSmith and Langfuse
{"id": "t001", "input": "I was charged twice this month", "expected": "billing", "metadata": {"critical": true}}
{"id": "t088", "input": "App crashes when I add a sixth label", "expected": "bug"}
{"id": "t141", "input": "Claim your refund now at bit.ly/…", "expected": "spam"}
evals/labeler.retest.tsscorers from other tools work as they are
import { Factuality } from 'autoevals'
import { fromPromptfoo } from '@rehearsal-labs/retest/scorers'

scores: {
  factual: Factuality,
  ...fromPromptfoo([
    { type: 'is-json' },
    { type: 'not-icontains', value: 'as an AI' },
  ]),
}

Write run above scores. TypeScript reads the object from top to bottom, and the error says so if they're swapped. autoevals scorers such as Factuality call their own model with their own key, so their cost isn't in Retest's budget.

Decided questions

Settled on 30 September 2026.

  1. File suffix: .retest.ts, setup tests included, so unit tests never collide.
  2. No escape from strict expect. To escape any, give the value a type: expect<number>(count).
  3. Inconclusive limit: 1% in evals, zero in regular tests. Judge calls that fail to arrive are retried twice. A malformed verdict gets no second try.
  4. Oldest TypeScript: 6.0, tested on 6 and 7.
  5. retest install: later, and only when asked. Pinned versions, with the version and file hash recorded in every run.
  6. Mixed failures: 1 wins once tests have run. 2 is for runs where nothing trustworthy came out.
  7. Default gate: the measured value. Use lowerBound for strict release checks.
