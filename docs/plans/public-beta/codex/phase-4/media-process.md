Lane "media-process": the Rust media processor, protocol version 2, and its TypeScript client. Phase 4 items 1 and 3 of docs/plans/public-beta/release-0.1.0.md. Read docs/plans/public-beta/codex/phase-4/common.md first; it binds this lane.

What exists: `media/` (crate `retest-media`, protocol version 1: one recording id per frame, PNG and JPEG frames decoded to raw RGB and piped to the host's ffmpeg, a bounded queue that drops the oldest frame, a timeline to constant frame rate, `.partial` output linked into place, one `ended` reply with counts and the video-to-capture mapping), `src/media/protocol.ts` and `src/media/client.ts` (`MediaProcess`, `Recording`), `proofs/media/` and the record docs/plans/public-beta/proofs/media.md, whose last section lists what was not shown. `src/media/capture.ts` (the `FrameSource` contract and `recordSource`) belongs to another lane and uses your client through its `MediaRecorder` and `RecordingTarget` types; keep those call shapes working or tell the orchestrator exactly what changes.

Deliver protocol version 2, in the crate and the client together:
1. Identity. A recording carries run, attempt, test, app and session ids; a frame carries its own frame id and may carry the action or observation id it belongs to; `ended` maps frame ids to video time. Ids are bounded strings; no secret and no app text is ever in a header.
2. Greeting and readiness. The greeting names the protocol version, the binary's version, its build identity (source revision when known, target triple) and the encoder probe's result; a readiness request is answered once the probe has finished; the first start never holds the input loop behind a hung ffmpeg beyond a stated bound. The client refuses a binary of another protocol version by name, with what to install.
3. Still images. A bounded command that resizes one PNG or JPEG and writes a thumbnail, with its own limits and a named failure, for screenshots and report thumbnails.
4. Frame sequences. A bounded command that returns the frames of a recording inside a time interval as timestamped images (bounded count, bounded size, evenly chosen when there are more), from a running or a finished recording, and says which stretches had no frame. It never invents a frame and never reports "nothing appeared".
5. Live view. An optional bounded stream of the newest frame of a recording, resized, for one watcher, with drops counted and no effect on the recording when the watcher is slow or gone.
6. Encoded frames. Measure the present route (decode, raw RGB to ffmpeg) against handing encoded frames to ffmpeg undecoded where no resize is needed: copies, allocations, bytes over each pipe, CPU and peak memory of the process and of ffmpeg, on the same recorded input. Choose by the measurement, keep whichever rule about one format per recording it needs, and record both sets of numbers as single-machine measurements, not a speed claim.
7. Queues and endings. Queue saturation, dropped frames, unavailable capture and encoder errors are counted and named in `ended`; finalization waits for the container under a deadline; a filesystem without hard links still finalizes (shown on one, or the fallback path shown by a test that forces it); a lost recording's `.partial` can be listed and removed by its owner through a command, so a later start at that output is not refused forever.
8. Shutdown and crashes. Every command is finite; a shutdown with recordings running ends each with a named status; nothing is left behind after a kill of the process or of ffmpeg. Keep the ownership rule of `media/src/process_ownership.rs` as the ownership fix lane left it.
9. Linux x64. Build the crate and run `cargo test` in the Linux container the repository already has (`docker/linux/run.sh`, read it first; use Docker only if it is already installed and running, start nothing system-wide). If that cannot be done here, record Linux as unverified with the reason.

As soon as the TypeScript types and client method signatures for 1 to 5 are stable, send the orchestrator a short message (SendMessage to "main") listing them, before the Rust side is finished: three other lanes build on them.
