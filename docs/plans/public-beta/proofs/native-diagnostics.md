# Native diagnostics and pixel evidence

The implementation adds parent-owned native stdout and declared network metadata sources, and native PNG evidence for screenshot checks. It adds no runtime dependency, export or CLI command. Runner/config wiring remains separate work.

## Sources and identity

`src/native/logs.ts` collects the stdout pipe of a launch whose pid and command were recorded. TaskDesk uses the binary's launch pipe. TaskPhone uses the stdout forwarded by `simctl launch --console`; the parent checks that the app is initially absent, then reconciles the launched pid and command through its app-scoped OS reading, while app stderr is discarded. The source never writes a raw app log file. `simctl launch --stdout` with a private named pipe was exercised first and produced no app bytes on this simulator, so it was removed rather than reported as working. The console route is explicit and has no fallback. It did not supply a usable pid acknowledgement in the real runs, so app text is never used to choose the pid. Both real fixture stdout sources passed after OS reconciliation was added.

Each line is a `console` record with `consoleType: 'stdout'`, `origin: 'native'`, the source name, owned pid, test, attempt, app and session. The line decoder handles split UTF-8 and secrets, caps buffered text, redacts and sanitizes before keeping a line, then applies the shared attempt entry/byte limits. Final redaction is bounded again when new secrets have been learned. Empty or blank-only output is unavailable. Loss, overflow and unfinished lines retain prior records and report partial capture with a reason. Disabled capture keeps no records. A native stdout stream cannot satisfy a strict JavaScript error rule.

`src/diagnostics/native-network.ts` reads the exact versioned service metadata shape. It rejects extra fields, including headers and bodies, invalid status/timing values and repeated or out-of-order sequence numbers. The parent opens the declared regular file before app launch and reads only appended records for the declared `ios` or `macos` client. Each correlated request/response/completion or transport-failure record carries the same record identity, `app-network-file` source and client. Routes are redacted and sanitized before record/byte limits apply. The reader and parser have separate input bounds.

No declaration yields `unavailable` with `the app provides no network source`. A missing declaration file yields `the declared network file is missing`; an unreadable one yields `the declared network file is unreadable`. An empty or other-client-only interval is unavailable. Invalid records, truncation, overflow and read failure are partial. No empty artifact claims complete capture.

The service's client name and file interval require an exclusive owner. They cannot distinguish two concurrent app copies using the same client name. This metadata source reports requests when their response ends or closes. It supplies no record of a request that has not emitted metadata, no transparent native traffic coverage and no causal link to a UI action.

## Pixel evidence

`src/evaluation/evidence.ts` accepts a native session's actual PNG, checks identity, dimensions, pixel decoding and bounds, copies its bytes, and saves that exact image for the judge. Each evidence record carries its capture source, timestamp, run-clock time, test, attempt, app, session, capture reference and PNG hash. The native capture's own observation reference is separate from a parent observation id. A multi-app check retains each capture's app and time.

The fake evaluator's `pixel-hash` mode decodes PNG pixels and looks up their SHA-256 in a table the test computed from actual captures. It ignores supplied text. Unknown pixels are inconclusive; a known defect fails. These checks prove transport, evidence identity and parent verdict retention. They do not measure a live model's visual accuracy.

TaskPhone's real screenshot proof passed through the parent evaluation path. The connected image passed, the non-loopback configuration showed a visible error and disabled sign-in, and that image failed even beside text asking the judge to ignore it. A later good image passed and the earlier required failure remained. Saved images were inspected. Their login fields are empty. The exercised source is `executor-screen`, with PNGs of 1206 by 2622 pixels.

TaskDesk's full-window capture and the combined phone/desktop check remain unverified. The production window source refused an overlapping window at layer 1000. The test preserved that failure and saved no image containing the other app's pixels. No existing assertion or capture rule was weakened. The combined test retains a separate exact task-id, title and open-state check through the fixture service's two client views; this is a service synchronization assertion, not a claim that both native UIs displayed that task.

Screenshots are pixels. Text redaction does not redact an image or video. No pixel masking capability was added or claimed.

## Wiring needed

The lifecycle owner must supply the log source before launch, check the existing launch blocker, adopt the returned recorded process, retain and await its stop hook, then await `AttemptDiagnostics.finishNative` after dispatched work has settled. An unreconciled launch remains uncertain and must not be signalled by an unverified pid or treated as undone. The config owner must expose a typed declared file/client source and maintain exclusive attempt ownership of that interval. Ordinary apps receive the unavailable status when they declare no source.

The macOS source still requires a genuinely clear app window before a full-window pixel claim can be verified. Any change to overlay recognition belongs to the native source owner and needs its own pixel proof. This work supplies no bypass.

## Runner and config wiring

The last build item of Phase 2 connects the sources above to the config, the native lifecycle and the runner. `src/native/logs.ts`, `src/diagnostics/**` and `src/evaluation/**` did not change.

### The declaration

A native target takes `diagnostics: { logs?, network? }` (`src/config/types.ts`). `logs` is `'stdout'`, the default, or `'none'`. `network` is `{ path, client }`, the shape `NativeNetworkDeclaration` reads, with `client` either `'ios'` or `'macos'` and `path` relative to the config. The loader makes the path absolute and keeps the declaration as `LoadedNativeDiagnostics`. A target that declares nothing has no `diagnostics`, which the runner reads as stdout and no network source. A wrong shape is refused by key: another `logs` value, another client, a blank path, an extra key in `network`, or the key on a browser.

A file and client belong to one app. `checkNetworkSources` in `src/config/read-apps.ts` compares declarations of one client through `folderKey`, so a link to the folder, or another case on a disk that ignores case, names the same file. Two apps on one file and client are refused, naming both keys. So are two targets of one app on different simulators, since two simulators can run at once. Targets of one app on the Mac, or on one simulator device and runtime, may share a declaration, because the desktop and device leases run them one at a time. The config cannot see a second Retest run on the same machine that reads the same file.

### The launch

`NativeSessionOptions` takes an optional `launcher` (`src/native/session.ts`, the one change there). The session checks the app's state and its launch blocker first, then asks the launcher. A launcher answers as a driver does and names the processes it recorded, which the session claims as its own beside those the operating system shows in the launch window. A launcher that answers undefined leaves the launch to the executor. `ios-simulator.ts` and `macos-app.ts` pass the options through unchanged and needed no edit.

`NativeBrowserAdapter` in `src/runner/native-pool.ts` installs that launcher when it opens the session. The run session gives it the attempt's log source before the app launches (`keepLogs`). For a target that keeps stdout, the launcher calls `launchLoggedNativeApp`. An answered launch hands the session the app process it recorded. A launch that threw is a failure with an unknown outcome and input `unknown`, since it may have started the app before it threw. A launch still running when the session stops, or past its budget, is `unknown` too. Whatever it settles to later stays with the adapter, and closing the adapter awaits its `stop()` after the session has ended the app and before the runtime closes, within the cleanup budget. A launch that never settles, or a stop that fails, is a `cleanup_failed` and the lease stays held. Nothing is taken as undone, and nothing outside the launch's own records is signalled.

On macOS the runner reads and drives only the app its own launch or activation named, and Finder otherwise. `FBSession.currentApplication` in appium-mac2-driver 4.3.6, Apache-2.0, read at the pinned checkout, returns `testedApplication`, which only those two routes set. So after a launch that kept its output, the adapter activates the app through the session. The first real run, before this, failed with the desk's tree belonging to another app. WebDriverAgent picks the active app itself and needs no activation on iOS.

A target with `logs: 'none'`, and every native target in a run with `capture: false`, is launched by the executor as before.

### The run

`#runPrepared` in `src/runner/run-session.ts` creates the attempt's diagnostics before any page opens. For each native app, `startNative` opens the declared file's interval and the log source is handed to the adapter, then the page opens and the app launches. Web pages start their capture once every page is open, as before. `finishNative` replaces `finish` on every path. It runs after the body, its settled commands, the host checks and the host AI checks, and before the failure screenshot and before any page or app closes. A page that fails to open, an interruption and a body that never ran each finish the native sources and keep their summaries. A policy failure still follows the test's own failure. `RunSessionOptions.native` lets a test supply stand-ins for the runtime and the logged launch. One existing call, `heldApp(...)?.whenFree()`, no longer compiled once `whenFree` became optional and now reads `whenFree?.()`.

Native screenshot evidence needed no change: `src/evaluation/evidence.ts` already freezes `NativePageAdapter.capture()` with its identity and time, and the real run below goes through it.

### Limits

- On macOS, `launchLoggedNativeApp` gives the app only its declared environment, and the app is a child of the Retest process. A SIGKILL of the Retest process runs no exit hook for it.
- The network file cannot tell two simultaneous copies of one client apart. The config guards apps and simultaneous simulators within one run only.
- The iOS logged launch relies on WebDriverAgent's own choice of the active app, as the executor launch does. The reference flow's broken-sync variant once read another app's tree on the phone; the same message was recorded before with executor launches.
- The unit runs use stand-ins for the runtime and the logged launch. The real logged launch ran only in the integration runs above.
- No desk screenshot check was attempted, since another app's window lies over TaskDesk on this Mac.
