# Recording in the runner

The runner records only when asked, one recording for each app session of an attempt. Evidence status is independent of the test's outcome. Configuration, recording events, retention, interrupted-folder rebuilds, source policy and bounded media finalization are implemented and exercised on real Chrome 154.0.8037.93 on macOS arm64. Source availability alone is not a platform claim.

## Evidence and identity

`recording.started` and `recording.finished` use the run event envelope and carry test, attempt, app and session identity. Recording outputs use the artifacts-policy module's attempt/session paths. Another attempt of the same test has another output. A start that is refused writes a finish record with its reason. Missing, empty or unsafe files cannot be reported as complete videos.

Each usable recording carries encoding, size, rate, frame counts and the mapping from capture time on the run clock to video time. Actions and assertions stay on that run clock. A partial recording names its gaps; an unchecked partial file is named separately. Incomplete media status, refused gaps, dropped source frames and capture cleanup failures stay incomplete even when ffmpeg produced a file.

`evidenceStatus.state` is complete, partial, unavailable or not_requested, per attempt and per run. A run that never asked for recording has no added status field or recording/media events. Required incomplete evidence is a run failure, `evidence_incomplete`; it changes no observed test outcome. A failed test continues to lead with exit 1.

## Shutdown and pixels

Recordings end after body and host checks and before failure screenshots and page disposal. Run shutdown closes media before browser/native resources. The settled media client checks its worker and ffmpeg encoders through process ownership. The runner preserves failed or timed-out cleanup as `cleanup_failed`, with a forced close event rather than a claim that the processes are gone. Encoder readiness, source starts/stops, frame release and leftover requests have bounded waits.

The runner calls the artifacts-policy module, including path checks and pixel decisions. Secret fills have an unread field fact, so capture is conservatively withheld until a new document or session end. The old source must be confirmed stopped before capture restarts. An unknown input outcome keeps the stretch open. Withheld frames are counted separately from dropped frames.

The evaluation lane added the same pre/post-capture checks in `src/evaluation/evidence.ts` while this takeover ran. Its two withholding regressions pass (`outside-unit-followup-2.log`). That source was not edited here. The policy is active when recording is requested or an app declares `pixels`; off runs without either setting retain previous screenshot behavior. No pixel-secrecy claim is made for that configuration.

The next worker can remove recording leftovers only from an unfinished sibling run whose recorded owner is confirmed gone. Active or unreadable owners are left alone. Artifact ancestors must pass the policy's link checks. The event uses `previousRunId`, preserving the current run's envelope.

5. Recording on Firefox, WebKit, Electron, iOS and macOS is not exercised here. Separate attempts are verified; automatic retry scheduling is not implemented.
