Collector findings from the per-engine diagnostics lane (docs/plans/public-beta/proofs/engines-diagnostics.md, section on driver findings, with file, line and scenario). Its cases are tests/integration/diagnostics-engines.test.ts: the same assertions on all three engines with no branching; do not edit that file. Firefox failed 5 checks of the fixture case. Fix the collector so they pass:
1. The serious one: with diagnostics capture on, Firefox changes the page under test. The fixture page logs an object with a getter; with capture on the getter runs (the page's title changes and its test fails), with capture off it does not. The cause is in how console arguments are read after the `log.entryAdded` subscription (src/diagnostics/firefox-collector.ts, around line 41). Observation must be read-only: capture never runs page code, never invokes a getter, never serialises an object in a way that does. Probes: /tmp/retest-diag-probe-firefox-result.json and /tmp/retest-diag-probe-firefox-off-result.json. If BiDi's serialisation of a logged object cannot be had without running the getter, take the entry's own text and mark the argument as not read, with the reason.
2. Firefox's own CORS message is recorded as an uncaught runtime error (around lines 185 to 198): browser messages stay out of runtime errors.
3. An unhandled promise rejection is recorded as `uncaught` (around line 191): record its real kind.
4. A dedicated worker's message is recorded as the page's (around line 204) though the scope claims dedicated workers (the review's F-7 too).
5. Message text is Firefox's own string, so objects read `[object Object]` (around line 205): every argument appears in the message's text as on Chrome, built without running page code (see 1), or the record is marked as cut.
6. The declared scope claims less than what is captured (records arrive from frames the scope lists as not covered): make the scope say what is true, or drop what is outside it; never both.
7. Requests carry no resource type: give it where BiDi reports it, name it unavailable in the scope's reason where it does not.
Each with a unit case in your own files that fails on today's collector.

The diagnostics file is being made stricter after its own review (docs/plans/public-beta/reviews/phase-3-review-diagnostics.md): a record from a frame or a worker must carry its true label whatever the scope declares, a record from an area the scope declares not covered is itself a failure, each scope area is its own subtest (so the network same-process-frame check, which never ran on Firefox because an earlier assertion threw first, will now run: a frame's document and fetch must be labelled `frame: 'child'`), the pending count is exactly 1, and the secrets case requires the object message and the long token to reach a record redacted. So the fix is to make the collector true, never to declare less scope. Run that file on Firefox before you report; it must reach every case without anyone editing it.
