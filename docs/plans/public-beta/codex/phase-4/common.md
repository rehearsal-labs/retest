Common brief for every Phase 4 lane of Retest 0.1.0. Your lane brief names this file; read it first, then the lane brief.

Retest is a TypeScript test engine at /Users/dragon/Documents/Projects/Gruvi/Products/retest: zero runtime npm dependencies, Node 24, its own drivers (Chromium over a pipe, Firefox over WebDriver BiDi, WebKit over the inspector pipe, iOS simulator and macOS apps through two installer-built XCTest executors, Electron through the Chromium driver), parent-owned verdicts: the parent process judges every check from its own observations and a test process can never soften a failure. Phases 1 to 3 are built; Phase 4 is "Rust media and complete evidence".

Read before anything else: AGENTS.md; docs/architecture.md; in docs/plans/public-beta/release-0.1.0.md the "Architecture rules" with its invariants list, "Evaluation and diagnostics in this release", and the whole Phase 4 section with its verification bullets; section 8 of docs/plans/public-beta/plan.md; "Evidence and Rehearsal scope" in docs/plans/public-beta/releases.md; docs/plans/public-beta/proofs/media.md (the Phase 1 media process, protocol version 1, and its list "Not shown, and what Phase 4 still needs"); docs/plans/public-beta/proofs/identity.md (record identity, the `FrameSource` contract, the Chromium screencast source); the Phase 4 section of docs/plans/public-beta/progress.md (the lane table says who owns which files; decisions there are binding).

Decisions that bind every lane:
- The media processor stays a separate bounded Rust process (`media/`, binary `retest-media`), spoken to over length-prefixed JSON headers with binary payloads on standard input and output. It runs the host's ffmpeg as a separate program and links no codec. ffmpeg is a declared prerequisite that `doctor` probes; Retest ships no codec. The binary is installed through an explicit, documented build or install path; nothing may depend on the developer's Cargo cache by accident.
- Protocol changes are versioned. Run folders keep `schemaVersion` 1 with additive changes only: every new event and field is in the schemas, validated on read and documented, and the record says whether a reader built before the change refuses the new folders.
- Evidence status is separate from the application outcome. A media failure never changes what the test observed, and missing or incomplete evidence is always named (`complete`, `partial` with a reason, `unavailable` with a reason), never an empty artifact that claims to be complete. A gap between frames never means nothing appeared, and sampling is never used to claim a fleeting event was absent.
- Text redaction does not redact pixels. Screenshots and recordings follow the documented pixel capture policy, and untrusted app text is escaped everywhere it is shown.
- A capture mode is advertised for a target only after the real target exercised it. A screenshot loop is never called a live frame stream.
- Recording is on only when asked; a run without recording behaves as it does today.

House rules: never commit, push, stash, checkout, reset or discard; never touch docs/roadmap.md, docs/plans/speed/handoff.md or pnpm-lock.yaml; edit only the files your lane brief gives you, and write down for the orchestrator (file, line, what and why) anything you need changed elsewhere; other lanes edit the tree while you run, so a failure inside their files is them mid-edit: wait and retry, never fix it. Heavy gates only through `lockf -t 0 /tmp/retest-heavy-gate.lock <command>` (npm run typecheck, npm run typecheck:proofs, npm run test:integration, every test or proof that starts a real browser, Electron, the simulator or the desktop; the lock is shared, if busy wait a minute and retry); unit files and `cargo test` need no lock; capture gate output to a file and read it after. Bare `tsc` in this checkout is the TypeScript 7 shim; use the npm scripts. Check `pgrep -f benchmarks/run.ts` before any test; never run `npm run bench` and make no speed claim: numbers you measure are recorded as single-machine measurements with their method. Zero runtime npm dependencies; a new crate needs its licence recorded and a reason; nothing under src/ imports Playwright, Appium or Selenium; no download unless the lane brief allows it. No `any`, no ts-ignore, no widening to unknown. Secrets never reach a file, report, frame header or log. Never end a process your own code did not launch and record (identity is pid plus start time; an unreadable command counts as unreadable). Native runs take this Mac's desktop and the simulator: open only what a test needs and close it; if anything prompts, stop and record it; a third-party always-on-top window may refuse a macOS capture: record it, never weaken the check. Plain words, and no estimated dates, deadlines, durations or plan codes in anything you write.

The rule above all: nothing may loosen what a passing test means. Never weaken, skip or delete an existing assertion. A capability is claimed only after the real target exercised it; what could not be exercised is recorded as unverified, most important first.
